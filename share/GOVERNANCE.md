# GOVERNANCE · 公共层治理（share/）

> 适用范围：`share/` 内一切被挂载项目共享的内容——`AGENTS.md`、`agent/`、`skills/`、`command/`、`tools/`、`runbooks/`、`opencode.json`。
> 挂载项目里以 `.opencode/` 路径访问的本层内容，即本文件所指对象。设计原理见仓库 `README.md`；新机安装见仓库 `INSTALL.md`。

## 1. 进入准则（什么可以进）

本层内容分三类，各按对应标准准入：

| 分区 | 内容 | 准入标准 |
|---|---|---|
| **通用区** | agents / skills / command / tools / 公共规则 / `opencode.json` | 跨项目通用、与具体项目/机器无关；稳定可复用的机制或工具；依赖可声明、可安装 |
| **机器事实区** | `runbooks/` | 允许本机基础设施事实（拓扑、端口、路径）；**换机必须整目录重写/替换**；只写凭据位置、绝不写凭据值 |
| **示例值** | 文档/agent 文案中的具体路径、项目名 | 必须明确标注为示例（"如…/当前为…"），且**不承载行为**（改了不影响执行正确性） |

通用区的入仓检查清单（逐项过）：

1. **路径中性化**：正文无本机/项目绝对路径（`C:\Users\<user>`、`D:\dev\...` 等）；工具/脚本用 `.opencode/...` 相对引用。
2. **无密钥与个人数据**：无 `.env`、token、密码、聊天记录、个人生活数据（扫描：`\.env|token|password|secret`）。
3. **命名空间**：agent / skill / command 名称与现有内容不冲突（opencode 按目录扫描合并，同名会互相覆盖/混淆）。
4. **描述达标**：skill / agent 的 `description` 含触发词与使用场景（否则不会被正确路由）。
5. **依赖声明**：需要的外部 CLI / 包 / MCP 在文档中写明安装与验证方式（对应 `INSTALL.md` 依赖章节）。
6. **项目实例不入仓**：项目专属内容放项目层（项目根 `AGENTS.md` / `opencode.json`）或深层层（仓库内 `.opencode/`），本层只放机制与通用实现。

## 2. 修改准则（怎么改）

**默认流程**：提案（动机 / 影响面 / 风险 / 验证方式）→ **审核确认** → 修改 → 校验 → 提交。

**两级门**：

| 级别 | 范围 | 要求 |
|---|---|---|
| **高危（先审）** | agent 权限（permission）、公共 `AGENTS.md` 规则/口令、`opencode.json`（权限/插件/模型）、`tools/` 行为、`runbooks/` 命令 | 改动前必须向用户提交提案并获得确认；提交信息记录确认结论 |
| **低危（先改后报）** | 文案、描述、示例、文档（`GOVERNANCE.md` / 说明类） | 可直接修改，但须提交留痕并在汇报中说明 |

**提交信息格式**：`<type>(<scope>): <摘要>` + 正文含「影响面 / 验证方式 /（高危）确认记录」。

**边界**：

- 在任一挂载项目会话里修改 `.opencode/` 内容 = 修改公共层（junction 直写），必须回到本仓库提交并说明理由；不允许"只改本机、不入库"。
- **禁止把本机/项目具体值写回本层**。需要新的可变值时，改为占位声明或指向项目/机器层的声明文件（如「入口由项目 `AGENTS.md` 声明」）。
- 模型不可用等本机差异，用项目根 `opencode.json` 的 `agent.<name>.model` 覆盖解决，不改本层 agent 文件。
- **权限作用域（已知限制，非缺陷）**：项目级权限规则（如 `.local` ask）只对**从该项目根启动的会话**生效，其他会话不受其约束。机器级红线（特定绝对路径、全机安全底线）放机器层 `~/.config/opencode/opencode.json`；通用红线放本层 `opencode.json`。

## 3. 验证与回滚

- 最小验证：JSON 文件用 `ConvertFrom-Json` 等做语法校验；涉及加载面（agent/skill/command/权限/插件）的改动，**重启 opencode** 后按烟测清单核对（agent 可发现、skill 可路由、`tools/` 可运行、权限 ask/deny 生效、MCP 连接）。
- 回滚：`git revert` 对应提交；junction 侧即时生效，重启 opencode 后恢复。

## 4. 登记

- 变更完成后同步更新仓库 `README.md` 的相应章节（本机审计/结构说明）。
- 机制级变更（分层模型、挂载方式、审批门）在提交信息中记录决策，必要时在 README 增补说明。

## 5. 定期审计

- 建议每轮功能批次后跑一次残留扫描：`qiu_k`、盘符路径（`[A-Za-z]:\\`）、密钥关键词；命中即评估是否属于「机器事实区/示例值」或需整改。
- 新机安装（`INSTALL.md`）后首件事：核对 `runbooks/` 是否与本机实际一致，不一致则整目录重写。
