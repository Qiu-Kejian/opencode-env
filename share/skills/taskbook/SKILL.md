# 任务书（施工单）机制（通用版）

> 本 skill 是**机制模板**；具体实例目录与索引留在各项目工作区（默认 `taskbooks/`，索引见该目录 `README.md`）。

## 为什么这样协作

- 新会话只读「公共 AGENTS + 项目 AGENTS + 本任务书」，token 成本固定且小。
- 不同任务可选不同档位模型：纯命令 → 弱/免费；文件创作 → 中；契约/结构对拍 → 强。
- 任务书自包含、可机检、有边界，弱模型也能稳定执行。

## 三条硬条件（写任务书时自检）

1. **自包含**：新会话零上下文可执行；必读文件精确到路径与小节。
2. **可机检**：验收 = 命令 + 期望输出，逐条可复制。
3. **边界清晰**：有明确「不做」清单；与任务书不符的事实 → 停止并写入执行记录。

## 生命周期

| 状态 | 含义 | 谁改 |
|---|---|---|
| 待生成 | 索引占位，任务书未写 | 主会话 |
| ready | 任务书就绪，可执行 | 主会话 |
| doing | 执行中 | 执行会话 |
| done | 执行会话自测完成并回填执行记录 | 执行会话 |
| accepted | 主会话复核通过（机器验收 PASS 且无 [人工] 项时自动） | 主会话 |
| rejected | 复核不通过，附返工说明 | 主会话 |
| 已废弃 | 人工决定不执行，不再排期 | 主会话 |

- 文件不移动、不改名；任务书文件内不写状态字段（头部只留建议模型 / 预估 / 依赖），状态只维护目录 `README.md` 索引 + 任务书内「执行记录」。
- 执行会话收尾：回填执行记录 → 更新索引状态 →（如接入看板）同步卡 → 按任务书「收尾」提交。

## 模板

见 `reference/template.md`。开场指令示例：`执行任务书 <工作区>/taskbooks/<编号>-<名称>.md`。

## 纪律

- 不扩范围、不猜路径；与任务书不符的事实即停并记录。
- 密钥只写位置不写值。
- 同一验收项失败 2 次即停。
